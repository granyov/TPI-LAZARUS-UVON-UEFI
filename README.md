# TPI LAZARUS / UVON — прошивка UEFI на базе U-Boot 2024.04

Прошивка промышленной платы **LAZARUS/UVON** компании TPI (Tech Pro Industries
LLC): Forlinx FET3568-C/C2, Rockchip RK3568, 4 ГиБ LPDDR4X.

Отдельного UEFI-компонента здесь нет. U-Boot 2024.04 сам предоставляет
UEFI-сервисы: загрузочный менеджер, загрузку `BOOTAA64.EFI`, файловое хранилище
EFI-переменных и таблицы времени выполнения. Для операционной системы плата
выглядит обычной машиной с UEFI.

Текущая версия — **v3.9**. Установлена на физической плате, readback сверен
побайтно; протокол испытаний — в [`release/`](release/).

Что нового в v3.9 по сравнению с v3.7:

- порядок загрузки настраивается и хранится на eMMC: по умолчанию SATA →
  eMMC → microSD → USB → любой носитель;
- кнопка RECOVERY при включении открывает меню: LOADER для RKDevTool (сам
  через 5 секунд), USB-диски eMMC и SATA, загрузка сервисного носителя,
  порядок загрузки, MaskROM;
- из LOADER плату переводит в USB-диски сервисная утилита на компьютере —
  консоль не нужна; после «извлечь» плата сразу грузится по новому порядку;
- консоль — 1 500 000 бод, как в руководстве на плату.

> **Собранных образов здесь нет — только исходники.** Из девяти компонентов FIT
> наши лишь два: `u-boot` (BL33) и device tree. Остальные семь — двоичные
> payload'ы TF-A и OP-TEE от Rockchip и Forlinx, права на которые принадлежат
> правообладателям. Прошивка собирается целиком, см.
> [`docs/BUILD.md`](docs/BUILD.md); vendor-входы подставляются свои и
> сверяются по SHA-256.

## Цепочка загрузки

```
BootROM
  → Forlinx MiniLoader (DDR/SPL)      заводской, без изменений
  → TF-A BL31 v2.3                    заводской, шесть payload'ов
  → OP-TEE 3.13 (BL32)                заводской
  → TPI U-Boot 2024.04 (BL33)         наш, он же UEFI
  → UEFI boot manager
  → BOOTAA64.EFI с ESP
  → ОС
```

Заводские DDR/SPL, TF-A и OP-TEE берутся из авторизованных образов **как есть**;
их SHA-256 сверяются при каждой сборке. Меняется только BL33.

## Что даёт прошивка

| Возможность | Подробности |
|---|---|
| SATA2 | нативно, через DWC AHCI и SCSI: диск виден как `scsi 0`, читаются GPT, ext4 и FAT |
| UEFI | boot manager, `BOOTAA64.EFI`, файловое хранилище EFI-переменных, runtime-таблицы |
| OP-TEE | 3.13 как BL32, его память (16 МиБ с `0x08400000`) зарезервирована для ОС. В Debian 13 (ядро 6.12) появляются `/dev/tee0` и `/dev/teepriv0`; ядро Astra 6.1 его не поднимает — см. «Возможное развитие» |
| MMC | все три контроллера, включая microSD carrier'а на SDMMC2 |
| Ethernet | оба порта RGMII, автосогласование, DHCP около 275 мс |
| Порядок загрузки | `tpi_boot_order` в окружении на eMMC; меняется из меню Recovery или сервисной утилитой `tpi-uvon` |
| Обслуживание | меню Recovery: LOADER (`rockusb`) для RKDevTool и USB-диски eMMC + SATA (`ums`) — обновление и доступ к носителям с компьютера без вскрытия корпуса |
| Консоль | UART2, 1 500 000 8N1 |
| Память | вся: `MemTotal` 3905 МБ, второй банк DRAM на `0x1f0000000` отдан ядру |

При каждой загрузке печатается баннер с названием изделия и версией загрузчика.

## Возможное развитие

### OP-TEE: доверенная среда для ключей и загрузки

OP-TEE — защищённая ОС в TrustZone процессора, параллельно с Linux. Её
память и данные недоступны Linux даже с правами root. Сейчас OP-TEE в цепочке
есть и запускается при каждом включении, но ничем не используется: ни ОС, ни
прошивка, ни сервисная утилита к нему не обращаются. Обязательно только одно —
ОС не должна трогать его 16 МиБ. Это задаёт `reserved-memory` в device tree
ОС, а `tpi-uvon diag` проверяет.

Пригодится, если появятся требования:

- **хранить ключи и сертификаты** прикладного ПО так, чтобы их нельзя было
  извлечь даже с root (защищённое хранилище, ключ кристалла);
- **доверенная загрузка и шифрование диска** с привязкой к плате — через
  программный TPM 2.0 (fTPM);
- **UEFI Secure Boot с защищёнными переменными**. Сейчас переменные UEFI лежат
  в файле на ESP; защищённый вариант — StandaloneMM в OP-TEE и область RPMB
  eMMC.

Что для этого потребуется:

- **В Astra.** Модулю `optee` её ядра 6.1 нужен FF-A, а TF-A 2.3 в цепочке его
  не поддерживает: `/dev/tee0` не появляется. Нужен модуль, собранный без FF-A
  (или ядро Astra, где это исправлено), подписанный для замкнутой программной
  среды, и `tee-supplicant`. В Debian 13 драйвер работает уже сейчас.
- **Доверенные приложения** собираются SDK Rockchip под этот OP-TEE и
  подписываются его ключом.
- **RPMB.** Ключ RPMB записывается в eMMC однократно и необратимо — только на
  подготовленных платах.

Прошивку здесь менять не нужно: OP-TEE уже стоит в цепочке. Исключать его из
неё смысла нет — экономия 16 МиБ памяти, а цепочка разошлась бы с заводской
проверенной.
