# Оборудование платы и device tree

Device tree прошивки — [`src/rk3568-tpi-lazarus.dts`](../src/rk3568-tpi-lazarus.dts),
производный от `rk3568-evb.dts` из дерева U-Boot и сверенный со схемой Э3
изделия. Он описывает то, что нужно самому загрузчику; device tree для
операционной системы — отдельный и богаче.

## Что перенесено со схемы

| Узел | Почему так |
|---|---|
| `&sata2`, `&combphy2` | SATA2 выведен через COMBPHY2, `phys = <&phy@fe840000 1>`, где 1 — `PHY_TYPE_SATA` |
| `&sdmmc2` | microSD carrier'а сидит на SDMMC2, разводка m1, 4 бита, 150 МГц |
| `&gmac0`, `&gmac1` | оба порта RGMII со своими задержками и сбросами PHY |
| `reserved-memory` | область OP-TEE на `0x08400000`, 16 МиБ, `no-map` |
| Узлы EVB | LCD-панели, тачскрин и светодиод EVB отключены: их выводы здесь заняты другим |

## Места, где легко ошибиться

**Сброс PHY задаётся дважды.** U-Boot ищет свойство `snps,reset-gpio` **на узле
MAC**, а описание EVB его не содержит вовсе. Ядро же читает `reset-gpios` на
узле самого PHY. Пока сброс был описан только по-ядерному, PHY оставался
в сбросе, приёмного тактирования не было, и программный сброс DMA не снимался —
`dhcp` заканчивался сообщением `EQOS_DMA_MODE_SWR stuck`. На этой плате линии
сброса — `gpio0 RK_PD5` для gmac0 и `gpio1 RK_PB0` для gmac1.

**Питание USB здесь безусловное.** Выводы, которыми им управляет EVB, на этом
carrier'е заняты сигналами `PCIE30X2_CLKREQn_M0` и `PCIE20_CLKREQn_M0`. Поэтому
у регуляторов USB свойства `gpio` удалены, а сами они объявлены постоянно
включёнными — иначе загрузчик дёргал бы чужие цепи.

**Второй банк DRAM.** Из 4 ГиБ адресное пространство ниже 4 ГБ вмещает не всё;
остаток лежит на `0x1f0000000`. Патч
[`src/rk3568-dram-high-bank.patch`](../src/rk3568-dram-high-bank.patch)
добавляет его вторым банком, иначе 256 МБ пропадают.

**OP-TEE надо зарезервировать.** TF-A оставляет OP-TEE резидентным в памяти.
Без узла `reserved-memory` ядро затирает эту область и падает на `SError`
в `copy_page`.

## Сборка device tree

DTB собирается вместе с прошивкой, отдельных действий не требует. Если нужно
посмотреть результат:

```sh
dtc -I dtb -O dts -o rk3568-tpi-lazarus.dts build/dts/upstream/src/arm64/rockchip/rk3568-tpi-lazarus.dtb
```
