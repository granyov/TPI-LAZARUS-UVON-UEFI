# Установка прошивки на чистую плату UVON

Порядок действий для платы, на которой прошивки TPI ещё нет — с заводским
U-Boot 2017.09 от Forlinx или с более старой нашей версией. Пишется только
раздел `uboot` в eMMC, 4 МиБ; операционная система и содержимое остальных
разделов не затрагиваются.

Корпус вскрывать не нужно: канал обновления даёт сам загрузчик.

## Что понадобится

| | |
|---|---|
| Файл | `TPI-LAZARUS-U-Boot-2024.04-SATA-UEFI-v3.7.img` из релиза [`v3.7`](../../releases/tag/v3.7) |
| Кабель | USB к разъёму OTG платы |
| Консоль | последовательный порт, 115200 8N1 |
| Утилита | `rkdeveloptool` на хосте |

SHA-256 образа — `eab1e7bc9cb33094de70f3ed3f47b9df26e3d017f08fdd28da45b5a401ac8361`,
размер ровно 4194304 байта. Проверьте перед записью:

```sh
sha256sum -c SHA256SUMS
```

### Права на хосте

`rkdeveloptool` работает без root, если пользователь состоит в группе, которой
правило udev отдаёт устройство Rockchip. В Debian и Ubuntu пакет
`rkdeveloptool` ставит `/lib/udev/rules.d/60-rkdeveloptool.rules` с группой
`rkdeveloptool`; нужные идентификаторы для RK3568 — `2207:350a` и `2207:350b`.

```sh
sudo usermod -aG rkdeveloptool "$USER"    # затем перелогиниться
rkdeveloptool ld                          # плата должна определиться
```

## Шаг 1. Войти в режим rockusb

Подключите консоль и питание, прервите автозагрузку.

| Прошивка на плате | Чем прерывается автозагрузка |
|---|---|
| Заводская Forlinx 2017.09 | **только CTRL+C** |
| TPI v3.x | любой клавишей |

Если попали в меню Rockchip, пункт `0` — выход в консоль. В приглашении:

```text
=> rockusb 0 mmc 0
```

Заводской U-Boot 2017.09 эту команду понимает, поэтому первая установка не
отличается от последующих обновлений.

Проверьте с хоста, что плата появилась:

```sh
rkdeveloptool ld
# DevNo=1  Vid=0x2207,Pid=0x350a,LocationID=102  Maskrom
```

Слово `Maskrom` в выводе — не ошибка: дескрипторы нашего гаджета отличаются от
заводского загрузчика, и утилита определяет режим так. На работу с разделами
это не влияет; не работает только `read-capability`.

## Шаг 2. Снять резервную копию

Обязательно. Это единственный способ вернуть плату к прежнему состоянию, не
вскрывая корпус.

```sh
rkdeveloptool read-partition uboot uboot-backup-$(date +%Y%m%d).img
sha256sum uboot-backup-*.img
```

## Шаг 3. Записать и сверить

```sh
rkdeveloptool write-partition uboot TPI-LAZARUS-U-Boot-2024.04-SATA-UEFI-v3.7.img
rkdeveloptool read-partition  uboot readback.img
cmp readback.img TPI-LAZARUS-U-Boot-2024.04-SATA-UEFI-v3.7.img && echo "совпадает побайтно"
rkdeveloptool rd
```

Сверяйте `cmp`, а не только размер: запись идёт по USB, и молчаливое
расхождение лучше обнаружить сразу, а не при следующей загрузке.

## Шаг 4. Проверить загрузку

После сброса в консоли должно появиться:

```text
## Checking u-boot 0x00a00000 ... sha256(dd92931990...) + OK
## Checking optee  0x08400000 ... sha256(4fcbcd3870...) + OK
INFO:    Using opteed sec cpu_context!
I/TC: OP-TEE version: 3.13.0-723-gdcfdd61d0
U-Boot 2024.04-tpi-lazarus-v3.7+ (Sep 18 2026 - 23:45:33 +0000)
Model: TPI LAZARUS UVON

       ___________
      /          /|     TPI LAZARUS UVON
     /          / |     Tech Pro Industries LLC
    /__________/  |
    |          |  |     Bootloader: 2024.04-tpi-lazarus-v3.7+
    |   T P i  |  |     SoC:        RK3568 / Forlinx FET3568-C
    |          | /
    |__________|/
```

Строки `## Checking … + OK` печатает заводской MiniLoader: он сверяет SHA-256
каждого компонента FIT до передачи управления. Отсутствие строки
`Error initializing runtime service opteed_fast` означает, что OP-TEE на месте.

Дальше загрузчик ищет систему: `scsi scan` находит SATA, `bootflow scan`
передаёт управление UEFI. **Без установленной ОС он остановится на приглашении
`TPI-LAZARUS=> ` — это нормально**, прошивка своё дело сделала.

Что именно ищет загрузчик и что нужно подготовить на носителе, чтобы он нашёл
систему, описано в [`docs/UEFI.md`](UEFI.md).

## Откат

Тем же каналом, из сохранённой копии:

```text
=> rockusb 0 mmc 0
```
```sh
rkdeveloptool write-partition uboot uboot-backup-ГГГГММДД.img
rkdeveloptool rd
```

## Если плата не доходит до приглашения U-Boot

Загрузчик Rockchip проверяет SHA-256 каждого компонента FIT **до** передачи
управления, поэтому повреждённый образ он просто не запустит и уйдёт в режим
загрузки по USB. Плата при этом видна тем же `rkdeveloptool`, и раздел
восстанавливается обычной командой `write-partition`. В eMMC лежат две
идентичные копии FIT — на `0x0` и `0x200000` — это штатная избыточность
Rockchip, воспроизводящая заводскую раскладку.

Если и это не помогает, на carrier'е есть цепь `RECOVERY_KEY`: по схеме Э3 она
идёт через NX7002AK на вывод SoM `ADC_VIN0_KEY/RECOVERY`. Удержание её при
подаче питания вводит загрузчик Rockchip в режим загрузки по USB. Где именно
выведена сама кнопка на конкретном исполнении корпуса — смотрите по
конструкторской документации изделия.

Аппаратный MaskROM (замыкание линий eMMC, чтобы BootROM не смог прочитать
загрузчик) — крайняя мера, требует вскрытия и здесь не описана: порядок зависит
от исполнения платы.

## Необязательно: проверка из оперативной памяти

Если хочется убедиться в образе, не трогая eMMC, положите chainload-файл
`TPI-LAZARUS-U-Boot-2024.04-SATA-UEFI-v3.7-chainload.bin` туда, откуда его
прочитает загрузчик, и запустите:

```text
=> load scsi 0:1 0x10000000 tpi-v3.7-chainload.bin
=> cp.b 0x10000000 0x00a00000 ${filesize}
=> go 0x00a00000
```

Грузить сразу в `0x00a00000` нельзя — U-Boot ответит `** Reading file would
overwrite reserved memory **`, потому что этот адрес попадает в его собственную
резервацию. Поэтому файл читается в свободный буфер и копируется оттуда:
`cp.b` такой проверки не делает.

Перед копированием стоит убедиться по `bdinfo`, что работающий U-Boot уже
перенёс себя в верхнюю память (`relocaddr` около `0xEDC14000`) — иначе он
затрёт сам себя.

## Что стоит знать заранее

- Записывается только раздел `uboot`. Разделы с ОС, данными и заводские
  `misc`/`recovery`/`oem` не затрагиваются.
- Прошивка не привязана к носителю ОС: она одинакова для плат с системой в eMMC
  и на SATA.
- Консоль заводской системы построена на Rockchip FIQ debugger — он
  перехватывает порт, если во входящем потоке встретятся байты `fiq`. Это
  свойство заводского ядра Linux, а не прошивки: сама прошивка держит обычную
  консоль на `serial2`, и под апстримным ядром перехвата нет. Учитывать это
  нужно, если передаёте файлы через консоль заводской системы.
